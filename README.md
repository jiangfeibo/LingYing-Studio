# 灵影 Studio · AI 课程制作

**把教学材料变成可观看、可更新的数字人课程。**

一份课件如何成为一节有讲解、有教师画面、有重点引导的课程？教师上传已有材料，说明需要讲解的章节与学生基础，再逐步调整例子、讲稿和课程表达。

**灵影 Studio（LingYing Studio）将材料处理、课程编辑、配音与数字人视频制作连接起来，已有两段完整课堂实例可供观看。** 项目的发展方向，是让教师通过对话持续调整课程内容，复用已有素材，并逐步加入动态知识演示，让课程随着教材和教学需求一起更新。

## 02 三个核心亮点

### 复用已有教学材料

教师积累的课件与教材可以成为制作起点。系统围绕材料组织讲稿，在已支持的课件结构上安排重点聚焦、激光笔等教学动作，让内容与讲解建立联系。

### 继续编辑课程内容

课程保留可编辑的页面、讲稿和相关素材。对于已支持的页面元素和模板，教师可以修订指定页、调整表达，再安排后续媒体制作。课程更新有明确的内容起点。

### 保存素材，组织视频交付

配音、教师片段和课件画面进入课程制作过程，后台任务保存实际输入与进展，已完成片段可在输入匹配时复用。最终成果可以合成为 MP4，用于离线观看、课程归档与教学展示。

这三个重点共同服务于一件事：**让课程既能交付，也能留下继续制作的基础。**

## 03 课程完成之后，还能继续生长

教材会更新，学生基础会不同，案例也会变化。课程的价值因此不只在第一次生成的视频，还在于内容、声音和媒体素材能否继续使用。

| 使用者与情境 | 怎样使用 | 下一步希望改变什么 |
| :--- | :--- | :--- |
| **教师备课与章节更新** | 复用已有课件，调整讲稿、例子和重点，再制作所需媒体 | 通过对话提出修改要求，减少重复整理和重新录制。 |
| **学生自学与复习** | 观看带讲解、教师画面和内容引导的章节课程 | 为不同基础设计不同解释深度，并保留教师审阅。 |
| **培训与知识维护** | 把已有文档和讲义组织成课程，持续更新变化的内容 | 保留素材与内容关联，让下一版制作沿用已有资产。 |

长期方向是将课件、讲稿、配音与视频积累为课程资产。教师可以围绕某个知识点持续修订，新的媒体模型也可以逐步加入制作能力。这些价值需要编辑、版本与真实输出共同支撑。

## 04 V3 开发方向：用对话持续修改一门课

教师不必每次重新填写一套制作流程。V3 的目标是让自然语言请求成为持续制作的入口：

> “这个例子太抽象，换一个学生更容易理解的例子。”
>
> “只修改这两页，保留其他内容。”
>
> “使用我已有的录音，重新制作这一段。”

这些请求分别涉及内容修改、课件编辑与媒体制作。V3 保留完整官方 DeepSeek Harness，让原 Agent 讨论、阅读、规划并选择能力，制作插件负责实际执行。用户可以先讨论，也可以直接制作，工具之间没有固定顺序。[DeepSeek Harness 官方项目](https://github.com/deepseek-ai/deepseek-harness)

| 新增能力 | 对教师请求的响应方向 |
| :--- | :--- |
| **课件** `slides` | 导入材料、处理版式、调整局部内容并导出课件。 |
| **配音** `speech` | 为文字配音，选择已配置声音，取得或复用匹配录音。 |
| **视频** `video` | 使用课件、已有录音和可选教师素材制作视频。 |

较长的配音与视频工作交给独立制作服务，保存输入、任务状态和真实文件；原生任务记录承担观察与完成通知。设计目标是让用户离开后仍能找回工作，回来时继续调整课程。

三个能力入口、后端适配和任务衔接已写入源码，完整部署与运行验收仍在后续阶段。上方两段课程展示现有项目成果。

## 05 下一步：让知识过程动起来

有些知识点需要精确文字，有些则需要看到变化。运动与受力、流动现象、物体交互或生活中的因果情境，都适合探索短场景辅助讲解。

我们计划在可控课件之外，引入类似 MiniMax H3 的生成能力，为某些知识点制作动态素材。例如，讲解一个现象时先展示短场景，再回到课件解释关键变量；讲解一个抽象概念时，用生活情境承接例子，让学生先观察，再理解。

| 教学变化 | 拟采用的做法 | 待验证条件 |
| :--- | :--- | :--- |
| **让过程可观察** | 为合适的知识点生成动态示范片段 | 科学正确性、时间关系与教学相关性。 |
| **让案例有情境** | 用人物与场景承接生活化例子 | 人物连续性、准确讲稿和声音一致性。 |
| **让课程有更多表达选择** | 将短镜头、教师片段和精确课件组织到课程中 | 多片段衔接、局部替换、成本与制作时间。 |

MiniMax H3 官方资料描述了多模态参考与联合音视频生成，单段输出范围为 4–15 秒。因此，长课程需要组织多个短片段；本地 Base 与完整高分辨率流程也存在差异。[MiniMax H3 官方说明](https://github.com/MiniMax-AI/MiniMax-H3)

这里描述的是发展设想。公式、代码、细小文字和图表继续由可控课件渲染承担，生成画面需要逐项检查；目前尚无本项目的 H3 集成课堂样例。

### 从输入到交付的现有入口

<p align="center"><img src="assets/07-classroom-workspace.png" alt="教学要求、材料上传、模型选择与课程任务入口" width="100%"></p>

用户上传材料并说明章节、受众和用途，系统准备课程内容，再按请求处理配音、教师片段与视频交付。后台任务可以查看实际状态，处理失败与重试。

主要限制集中在材料与输出质量：复杂课件的字体、动画和特殊版式可能无法完全还原；语言模型生成的事实和教学逻辑需要教师审阅；口型、表情和长视频合成受模型、素材与资源影响。现有实例证明具体课程能够交付，尚未证明任意教材都能无人工干预地稳定生成，也没有学习效果优于真人授课的评估结论。
